# Decisions and deviations

Every deviation from DESIGN.md, and every choice DESIGN.md left open, with the date and reason.

| Date | Decision | Reason |
| --- | --- | --- |
| 2026-10-15 | Firestore region **us-east1** for both `spoilnot-dev` and `spoilnot-prod`. | Chosen by the owner (DESIGN 15 left it open). Cannot be changed later. |
| 2026-10-15 | New products default to **imperial** units. | Chosen by the owner (DESIGN 15 left it open). |
| 2026-10-15 | Font: **Manrope** variable font, bundled in `res/font`, licence in `assets/licenses/manrope-OFL.txt`. | Owner approved; DESIGN 6.4 allowed Manrope or Inter. |
| 2026-10-15 | All emulator work uses the project ID **`demo-spoilnot`**, not `spoilnot-dev`. Dev debug builds get it from `app/src/dev/debug/google-services.json` (the plugin prefers that path over `src/devDebug`); dev release builds keep `spoilnot-dev`. | `demo-` projects are emulator-only, so tests cannot reach real data even by mistake, and no `firebase login` is needed. Matching IDs also keep the app's data visible in the emulator UI and make Auth and Firestore emulator tokens agree. `firebase/.firebaserc` keeps `dev` and `prod` aliases for deploying rules. |
| 2026-10-15 | Both `google-services.json` files are committed (`app/src/dev`, `app/src/prod`). | They hold identifiers, not secrets (DESIGN 12.2), and CI needs them to build. Follow-up for M7: restrict the Android API keys in the Google Cloud console to the package names. |
| 2026-10-15 | Light **Soon** status color is **#A05F00** instead of #B26A00. | #B26A00 is only 4.04:1 on the light surface, below the 4.5:1 that DESIGN 6.4 requires. #A05F00 is the same hue at 4.84:1. Enforced by `StatusColorsContrastTest`. |
| 2026-10-15 | Theme colors generated with Material Color Utilities 0.3.0 (tonal spot scheme, seed #2E7D5B). | This is the library behind Material Theme Builder; output is identical to its default scheme. The newest npm release (0.4.x) has a broken ESM import. |
| 2026-10-15 | Dev debug builds declare `ACCESS_LOCAL_NETWORK` and request it once at startup; instrumented tests grant it. A dev-debug-only network security config allows cleartext to 10.0.2.2, localhost and 127.0.0.1. | Android 17 blocks apps targeting API 37 from private-network addresses such as the emulator host, and the emulators speak plain HTTP. Prod and release builds never declare the permission and stay TLS only (DESIGN 12.2). |
| 2026-10-15 | Backups disabled: `allowBackup=false` plus data-extraction and full-backup rules that exclude everything. | Keeps the Firestore cache from moving to other devices (DESIGN 12.2, controls 5 and 6). Required by lint on API 31+. |
| 2026-10-15 | CI runs `spotlessCheck lintDevDebug testDevDebugUnitTest assembleDebug` instead of `lintDebug testDebugUnitTest`. | With product flavors AGP has no aggregate `lintDebug` or `testDebugUnitTest` task. Unit tests and lint are flavor-independent today; `assembleDebug` still builds both flavors. |
| 2026-10-15 | ktlint uses the `android_studio` style with trailing commas allowed, configured in the root `build.gradle.kts`. | Spotless did not pick up `.editorconfig` sections; trailing commas keep diffs small. |
| 2026-10-15 | Icons come from `material-icons-extended` (Rounded and Outlined Material Icons). | Material Symbols are not published as a Compose artifact; the extended Material Icons set is the closest maintained equivalent. R8 strips unused icons in release builds. |
| 2026-10-15 | Crashlytics, splash screen, DataStore, Coil and screenshot tests (Roborazzi) are deferred to the milestones that need them (M2 and M6). | M0 has no screens with content to snapshot and no settings to store; adding them now would be untested scaffolding. |
| 2026-10-15 | Settings route carries its tab (`SettingsRoute(tab)`). | Each tab can open Settings on its own back stack; a shared key would collide in saved state. |
| 2026-10-15 | `compileSdk` and `targetSdk` 37, AGP 9.4.1 (built-in Kotlin), Kotlin 2.4.21, Gradle 9.8.1, Compose BOM 2026.09.00, Material 3 1.4.0, Navigation 3 1.2.0, Firebase BoM 35.0.2, Hilt 2.60.1. | Latest stable versions on 2026-10-15 (DESIGN 0 and 7.3). |
| 2026-10-16 | M1: `users/{uid}` has an optional **`pendingJoin`** `{householdId, householdName, code}` (rules allow it on create and update). | The design gives a waiting requester no way to find their request again on another device or after reinstalling; the profile is the one private document they always read. |
| 2026-10-16 | M1 rules: the default grocery list is created under **`existsAfter`** of the creator's membership instead of `isMember`. | Verified against the emulator: with `isMember` (which sees the state before the batch) the household-creation batch is rejected. |
| 2026-10-16 | M1 rules tightened beyond the 12.3 draft: an invite code can only be created as the household's current code; a household can only be created together with its owner membership; the owner membership can only be created with a new household; `joinedAt` must be the server time; a join request can only be decided while pending; `role` is limited to owner or member; `expiryDate` must be a string. | Closes gaps the draft left open (stray codes, re-deciding requests, arbitrary roles). All covered by the 50-case rules test matrix in `firebase/test/rules.test.js`. |
| 2026-10-16 | Household listeners retry a permission refusal once this device's own pending writes are acknowledged (`retryAfterOwnWrites`); only a second refusal means the membership is gone. | Found by the two-user test: right after creating or joining, a listener can reach the server before the membership write, the rules refuse it, and the membership watcher wrongly sent the user back to the gate. |
| 2026-10-16 | Account deletion checks the password on a separate, temporary FirebaseApp, does all Firestore work, clears local data, and only then deletes the sign-in, reauthenticating at that point if Firebase requires it. | Against the emulators, Firestore deletes made right after `reauthenticate()` on the same app were refused by the rules (reads and other writes still worked). This order never writes after a reauthentication and still stops on a wrong password before anything is deleted. |
| 2026-10-16 | Removing a member, transferring ownership, leaving and deleting a household use confirmation dialogs instead of an 8-second Undo snackbar. | These cannot be undone once the server applies them: a removed member loses read access immediately, and a deleted household is gone. DESIGN 6.1 asks for Undo on destructive actions; the confirmation is the safe equivalent here. |
| 2026-10-16 | A join request that disappears without an answer is shown as "Request expired" and can be dismissed. | Requests older than 7 days are pruned by the reminder job (M4); the requester needs a clear end state. |
| 2026-10-16 | Activity events: pantry events (`stock_added`, `discarded`) are written from M2 because product detail shows the last 20 events and Throw away must log its reason; the rest (`member_joined`, grocery and recipe events) start with their features or the M6 activity log. | Each event is written only where a screen reads it. |
| 2026-10-16 | Settings in M1 has only Account (name, email, verification, sign out, delete account) and Household. Editing the display name is not offered yet. | Notifications, Appearance, Data and About arrive with M4 and M6. DESIGN does not list a display-name editor in 5.1. |
| 2026-10-16 | Instrumented tests run in Hilt's test application (`HiltTestRunner`) with a debug-only `HiltTestActivity`; two-phone tests use one named FirebaseApp per simulated phone. | Screens use Hilt ViewModels, and separate FirebaseApps give each simulated user their own sign-in and Firestore cache. |
| 2026-10-16 | M2: products keep **`recentShelfLifeDays`** (the last 5 shelf lives, newest last) next to `typicalShelfLifeDays`. | DESIGN 5.2 learns from "the last 5 batches", but batches are deleted when used up, so they cannot be re-read later. Keeping the five numbers on the product makes the median exact. |
| 2026-10-16 | Activity events carry a top-level **`productId`**; product history queries `activity where productId == X` and sorts on the device. | An equality-only query uses the automatic single-field index, so no composite index is needed (DESIGN 8.4). |
| 2026-10-16 | Rules: a member may delete their **own** activity event (`actorUid == me`), not only the owner. | Undo of Throw away must remove its `discarded` event. Covered by two new rules tests (52 in total). |
| 2026-10-16 | Pantry writes return as soon as they are applied to the local cache; server rejections are reported afterwards through `PantryWriteErrors` and shown as a message. | DESIGN 9.3 and 9.5: the cache is the optimistic UI and the app must work offline, so an action cannot wait for the server. |
| 2026-10-16 | Pantry rules live in a pure `PantryService` that turns each action into a list of `PantryChange`s; the repository only applies them in batches of 400. | Keeps add-or-merge, unit locking, shelf-life learning, restock re-arming and Undo testable without Firestore (DESIGN 7.2). |
| 2026-10-16 | Location filters and grouping show only the matching location's batches; a product stored in two places appears in both groups. Status filters (Expiring soon, Expired) likewise show the matching batches. Expiring soon means today to 3 days; Expired is its own chip. Out and Low always use the product's overall total. | DESIGN 5.2 does not say how a multi-location product is filtered or grouped. |
| 2026-10-16 | Status chips use a short text ("Tomorrow", "3 days", "Expired", "Oct 20"); batch rows and screen readers get the full wording from the status table. Week (4 to 7 days) uses the fresh color. | The table's wording is too long for a chip on a phone row; 6.4 lists no color for the week status. |
| 2026-10-16 | Tapping a pantry row expands it; tapping the product name opens product detail. The Add and Edit sheets keep the save button pinned below the scrolling fields. | DESIGN 5.2 asks for both actions on one row; found on the device that the save button was below the fold. |
| 2026-10-16 | The remote-change row highlight (DESIGN 6.4 motion) moves to M6 with the other animations. The rule that a remote change never moves the list during a scroll is in M2: list updates are held while a scroll is in progress. | The hold is a MUST and affects usability; the highlight is polish. |
| 2026-10-16 | Compose component tests and Roborazzi screenshots run on the JVM with Robolectric (API 36). Screenshots are recorded with `./gradlew recordRoborazziDevDebug` into `app/build/outputs/roborazzi` for review and are not committed; CI renders them without comparing images. | Image comparison across macOS and Linux CI is fragile (fonts, antialiasing); rendering every variant still catches crashes and layout errors. Robolectric 4.17 is pinned to API 36, its well-supported level. |
| 2026-10-17 | Location in the Add and Edit sheets is a row of wrapping filter chips instead of a segmented control (date type stays segmented). | Found by the 200% font screenshots: four segments truncate to "Fridg", "Freez". DESIGN 5.2 does not name the control for location; 6.8 requires 200% font. |
| 2026-10-17 | Unit tests run with `--add-exports java.base/jdk.internal.access` and `--add-opens java.base/java.io`. | Robolectric 4.17 needs them on Java 21 (CI and local); without them every Robolectric test fails before running. |
| 2026-10-17 | The rules-test harness retries `clearFirestore()` up to 3 times. | Reproduced locally: a long-running emulator just used by the Android tests answers the first clear with HTTP 500. CI starts a fresh emulator each run. |
| 2026-10-17 | M3: writes go through one `HouseholdWriter` (core) that applies any mix of feature changes (`PantryChange`, `GroceryChange`) in batches; each feature's data layer registers a `FirestoreChangeMapper` (Hilt multibinding). `Actor` and `Undo` moved to `core/write`. | "Add to pantry" and the restock engine must change pantry and grocery documents in one batched write (DESIGN 5.3, 9.6). |
| 2026-10-17 | The restock engine is a pure function (`RestockEngine.plan`); `RestockRunner` runs it on every phone from `SpoilNotApp.onCreate`, on products, stock and list names (debounced 300 ms, cache snapshots included). It checks the local cache for `low_{productId}` instead of listening to the default list's items, and does not resend an identical plan within 30 s. | DESIGN 9.6 needs createdAt only when the item is not cached; a permanent item listener would cost reads (9.7). The repeat guard stops a write loop if the server ever rejects a plan. |
| 2026-10-17 | Rules: a grocery list other than the household's first is never the default; `isDefault` cannot change; list names are 1 to 60 characters; only the owner deletes the default list (when deleting the household). | Invariant 5 (exactly one default list). Covered by 4 new rules tests (56 in total). |
| 2026-10-17 | Quick add reads a leading quantity and unit ("2 kg rice", "12 eggs"); a number on its own is a name. A typed name that matches a pantry product links it, so the item gets its category (aisle). | DESIGN 5.3 asks for a quick-add field and grouping by category; this fills both without extra taps. |
| 2026-10-17 | The list switcher and list management (new, rename, delete) are in a Lists menu in the top bar rather than a dropdown on the title. Grocery items delete with a swipe in either direction or from their menu, with Undo. | The large top app bar title is not a control; the menu is reachable and accessible. |
| 2026-10-17 | "Add to grocery list automatically" starts on the first time Keep at least is set (Add item sheet and product detail), and the whole row toggles it. | Found on the device: setting Keep at least on an existing product left the switch off, so nothing was added. |
| 2026-10-17 | Robolectric runs with a plain `android.app.Application`. | The real app now starts the restock runner (Hilt, Firebase), which component tests do not need. |
| 2026-10-17 | Add to pantry writes up to 400 operations atomically; a larger shop (roughly 100 items or more) is split into several batches. | Firestore's batch limit (DESIGN 8.5). |
| 2026-10-17 | M4: the reminder job's TypeScript runs directly under Node 24 for tests (type stripping) and is compiled with `tsc` for the workflow (`rewriteRelativeImportExtensions`). TypeScript 7.0.2, firebase-admin 14.5.0. | No test runner or bundler to maintain; the workflow runs plain JavaScript as in DESIGN 10.4. |
| 2026-10-17 | The digest body is one line, "Throw away: Milk. Tomorrow: Yogurt, Eggs.", as in the DESIGN 5.4 example, with a separate "Past best before:" group for expired best-before items (so up to five groups). Two batches of one product count once. | DESIGN 10.3 says best-before items use softer wording; a notification body shows best as one line. |
| 2026-10-17 | A dry run changes nothing: no sends, no `lastDigestDate`, no token deletion, no pruning. Manual runs from GitHub default to a dry run; scheduled runs are live. | DESIGN 10.5 asks for a dry run that logs messages; a manual run should never surprise anyone. |
| 2026-10-17 | Pruning walks the households and queries each one's `activity` and `joinRequests` (single-field indexes) rather than a collection-group query. | Collection-group range queries need extra index configuration (DESIGN 8.4 wants none); households are few. |
| 2026-10-17 | The FCM token is stored under `users/{uid}/devices/{Firebase Installation ID}`; the time zone is written at app start when it changed; the device document is deleted on sign-out (account deletion already deletes all devices). | DESIGN 10.2. The installation id is stable per install and needs no extra storage. |
| 2026-10-17 | Release builds are signed with the debug key while there is no `keystore.properties` (the upload keystore arrives in M6). | The live M4 test needs a build against the real `spoilnot-dev` (debug builds use the emulators and cannot get FCM tokens). |
| 2026-10-17 | The notification permission explanation appears once, after the first dated item is saved and only if the permission is missing; the answer is remembered in DataStore. Settings > Notifications offers 5 AM to 9 PM, the four stages, expired mode, a test notification, a permission banner and a battery-settings tip. | DESIGN 5.4, 10.2 and 15. The job sends nothing after 22:00, so later hours would never deliver. |
| 2026-10-17 | `MainActivity` is `singleTop`, so tapping a digest while the app is open delivers the route through `onNewIntent`. | DESIGN 10.2 reads the route in `onCreate` and `onNewIntent`. |
